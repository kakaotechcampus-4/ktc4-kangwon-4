# 임차형 소규모 카페의 공식 폐업 절차

> 소유: AI · 작성·공식 안내 열람일: 2026-09-20
>
> 대상: 폐업을 결정한 비프랜차이즈 임차형 소규모 카페 사업자.
> 세무 안내는 개인사업자를 중심으로 하며, 법인 청산 절차는 포함하지 않는다.

이 문서는 **공식 안내에서 확인한 절차와 Case별로 확인할 조건**을 정리한 참고 자료다.
문서를 작성한 날짜가 법령의 시행일이나 사람의 정책 검수일을 뜻하지는 않는다.
관할기관의 실제 처리 결과, 개별 계약의 해석, 세액, 지원 자격을 확정하지 않는다.

요청 시 Agent가 읽는 자료와 검수 방식은 [절차 지식 관리](./procedure-knowledge.md)를 따른다.
이 문서를 추가해도 검수 스냅샷이나 DB 레코드가 자동 갱신되지 않는다.
아래의 준비 순서는 서비스가 확인할 항목을 정리한 것이며, 모든 Case에 적용되는 법정 순서는 아니다.

## 1. 먼저 구분할 것

- **사업자등록 폐업신고**와 **식품영업 폐업신고**는 담당 기관과 신고 대상이 다르다.
  대상 업종의 통합폐업신고는 한 창구에서 접수할 수 있으므로, 둘 사이에 반드시 순차 관계를 두지 않는다.
  국세청 안내는 음식업 등을 통합 접수 대상으로 설명한다.
  [국세청 휴·폐업 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7780&mi=2447)
- **사업자등록 폐업신고**와 **폐업분 세금 신고·납부**도 별개로 확인한다.
  카페 폐업 안내는 부가가치세 확정신고와 종합소득세 신고를 각각 설명한다.
  [찾기쉬운 생활법령정보: 카페 폐업 신고](https://www.easylaw.go.kr/CSP/CnpClsMainBtr.laf?ccfNo=5&cciNo=1&cnpClsNo=1&csmSeq=706&popMenu=ov)
- **점포 반환·원상복구·보증금 정산**은 임대차 관계의 처리다.
  신고 접수만으로 임대차가 끝났거나 원상복구가 완료됐다고 판단하지 않는다.
  임대차 종료 시 반환·원상회복 의무의 일반 근거는 다음 안내에서 확인할 수 있다.
  [찾기쉬운 생활법령정보: 임차인의 권리·의무](https://easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=3&cciNo=2&cnpClsNo=2&csmSeq=627&popMenu=ov)

## 2. 신고·철거 전에 확인할 조건

### 임대차 종료와 원상복구

사용자가 임대인과 확인한 계약 종료 조건, 반환 시점, 원상복구 범위, 보증금 정산 내용을 확인한다.
원상회복의 일반 의무가 있다는 사실만으로 전부 철거, 비용 전액 부담, 특정 반환일을 만들지 않는다.
합의 내용이 확인되지 않았으면 `restoration_scope`와 `demolition_required`를 추정해 채우지 않는다.
계약의 효력·비용 분담에 다툼이 있으면 법률 전문가 확인이 필요한 사안으로 둔다.
[임차인의 권리·의무](https://easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=3&cciNo=2&cnpClsNo=2&csmSeq=627&popMenu=ov)

보증금을 돌려받지 못한 상태에서 점포를 인도하거나 사업자등록을 정리하려는 경우에는 권리보전 문제도
확인한다. 공식 안내는 대항력 유지에 점유·사업자등록이 관련되고, 임대차 종료 후 보증금이 미반환된
경우 임차권등기명령 제도를 설명한다. **개별 Case에서 폐업신고를 미루거나 등기를 신청하라고
자동 결정하지 않고**, 법률 전문가·관할기관에 신고 의무와 권리보전 방법을 함께 확인하도록 한다.
[찾기쉬운 생활법령정보: 상가건물 임대차보호법](https://easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=5&cciNo=1&cnpClsNo=2&csmSeq=1171)

### 철거비 지원을 검토하는 경우

기업마당의 2026년 원스톱폐업지원 공고에서 사업정리컨설팅·점포철거비·법률자문·채무조정의 존재와
세부사업별로 신청기간이 다르다는 점을 확인했다. 이 사실만으로 특정 사용자를 지원 대상으로 정하지 않는다.
[기업마당 공식 공고](https://www.bizinfo.go.kr/sii/siia/selectSIIA200Detail.do?pblancId=PBLN_000000000117676)

철거 전 지원조건 확인은 **팀이 검수할 확인 순서**다. 모든 지원사업에서 사전 승인이 필수라는 뜻은 아니다.
신청을 검토한다면 최신 수정 공고와 첨부에서 다음을 확인한 뒤 실제 철거·증빙 준비 방법을 안내한다.

- 신청 시점과 철거 시점의 관계, 이미 철거한 경우의 취급
- 임차·업종·폐업 상태·기존 수혜에 관한 조건과 제외 대상
- 철거 전후 사진, 계약·지출 증빙 등 실제 요구서류
- 접수 가능 여부, 예산 소진 여부, 접수·보완·정산 절차

이 확인항목은 검수 목록이며 현재 공고의 확정 조건을 전사한 것이 아니다.
현재 저장소의 합성 지원 카탈로그를 실제 희망리턴패키지 자격 근거로 사용하지 않는다.
최신 수정 공고와 첨부 본문 검수가 끝나기 전에는 금액·마감일·수급 가능성을 확정하지 않는다.

### 근로자가 있거나 최근 퇴직한 경우

고용 종료 방식, 근로자별 마지막 근무일, 임금·퇴직급여 정산 여부를 확인한다.
고용노동부는 상시근로자 5인 미만 사업장에도 해고예고·금품청산 등 적용 규정이 있음을 안내한다.
따라서 직원 수만 보고 노무 절차를 생략하지 않는다. 해고예고 예외와 퇴직급여 적용 여부는
근속기간·근로시간·종료 사유 등을 근거로 확인하며, Agent가 최종 판단하지 않는다.
[고용노동부: 5인 미만 사업장 적용 안내](https://1350.moel.go.kr/rtmview.do?id=1000281283)

금품청산은 지급 사유 발생일부터 **원칙적으로 14일 이내**이며, 특별한 사정이 있는 경우 당사자 합의에
따른 기일 연장 규정이 있다. 이는 사업자등록 폐업신고일로부터 무조건 14일을 계산하는 규칙이 아니다.
미지급 또는 다툼이 있으면 고용노동부·노무 전문가 확인을 다음 행동 후보로 둔다.
[고용노동부: 금품청산 안내](https://1350.moel.go.kr/rtmview.do?id=1000316171&page=1&type=ALL)

## 3. 사업자등록·식품영업 폐업신고

| 절차 | 확인한 공식 내용 | 사용자에게 확인할 결과 |
|---|---|---|
| 사업자등록 폐업신고 | 폐업 시 지체 없이 신고. 세무서 제출 또는 홈택스·모바일 신고 경로가 안내되어 있다. 서면 신고의 기본 자료는 휴업(폐업)신고서와 사업자등록증이다. 인허가 업종의 추가 자료와 접수 방식은 관할기관에서 확인한다. | 접수 여부, 신고한 실제 폐업일, 처리 결과 |
| 식품영업 폐업신고 | 실제 영업신고·허가의 종류와 관할 시·군·구 등을 확인한다. 폐업신고서에 영업허가증 또는 영업신고증을 첨부하는 절차가 안내되어 있다. | 관할기관, 신고 대상 영업, 접수·처리 결과 |
| 통합 접수 선택 | 음식점 등의 식품영업 폐업신고와 사업자등록 폐업신고를 함께 제출하는 경로가 있다. | 두 신고가 함께 접수됐는지와 각 처리 결과 |

근거: [국세청 휴·폐업](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7780&mi=2447),
[카페 폐업 신고 — 식품위생법 제37조·시행규칙 제44조 안내](https://www.easylaw.go.kr/CSP/CnpClsMainBtr.laf?ccfNo=5&cciNo=1&cnpClsNo=1&csmSeq=706&popMenu=ov).

홈택스 화면의 메뉴 명칭은 변경될 수 있으므로 오래된 안내의 메뉴 경로를 고정 UI 계약으로 사용하지 않는다.
신고서 작성·제출은 사용자가 공식 창구에서 한다. Agent는 대행 제출하지 않는다.

국세청은 일반적인 폐업일을 **사업을 실질적으로 폐업한 날**로 설명한다.
따라서 `planned_closure_date`를 실제 폐업일이나 신고 처리일로 간주하지 않는다.
부가세 신고서 제출로 폐업신고를 갈음하는 등 예외 경로도 공식 안내에 있으므로,
폐업신고와 세금 신고 사이에 일률적인 완료 선행 조건을 만들지 않는다.
[국세청 휴·폐업일 기준](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7780&mi=2447)

## 4. 폐업 후에도 별도로 확인할 세금

| 항목 | 공식 안내에서 확인한 원칙 | 추가 확인 |
|---|---|---|
| 폐업분 부가가치세 | 폐업일이 속한 과세기간의 개시일부터 폐업일까지를 신고하며, 일반 안내의 기한은 폐업일이 속한 달의 다음 달 25일이다. | 실제 폐업일, 일반·간이 등 과세유형, 적용 세법, 기한 연장·휴일 조정, 신고·납부 결과 |
| 개인사업자 종합소득세 | 해당 연도 종합소득에 대해 원칙적으로 다음 해 5월 1일~31일에 신고·납부한다. 성실신고확인서 제출자 등에는 별도 기한이 있다. | 다른 소득과의 합산, 신고 대상 여부, 해당 연도 공지, 개별 연장 여부 |
| 직원 관련 원천세·지급명세서 등 | 직원 급여·퇴직 관련 처리가 있으면 별도 세무 확인항목으로 둔다. | 지급 소득 종류와 지급일에 따른 의무·기한을 세무서·세무 전문가에게 확인. 이 문서에서 일괄 기한을 정하지 않음 |

부가세 근거: [카페 폐업 안내의 부가가치세 확정신고·납부 본문](https://www.easylaw.go.kr/CSP/CnpClsMainBtr.laf?ccfNo=5&cciNo=1&cnpClsNo=1&csmSeq=706&popMenu=ov).
종합소득세 근거: [국세청 신고납부기한](https://nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7665&mi=2224).
지급명세서 확인 창구: [국세청 지급명세서 제출 안내](https://b.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=8631&mi=12309).

생활법령 카페 페이지의 소제목에는 폐업 전 부가세 완납이라는 표현이 있지만, 같은 페이지의 상세 본문은
다음 달 신고기한을 설명한다. **소제목만으로 세금 납부 완료를 폐업신고의 필수 선행 조건으로 만들지 않는다.**
세액과 실제 달력 날짜는 이 문서에서 계산하지 않는다. Agent가 날짜를 제시하려면 검수된 규칙,
확인된 기준일, 필요한 예외 처리와 코드 계산 근거가 있어야 한다.

## 5. 국민연금·그 밖의 사회보험

국민연금공단의 사업장 탈퇴 안내에서 확인한 범위는 다음과 같다.

| 항목 | 국민연금 사업장 탈퇴 안내 |
|---|---|
| 신고 대상 | 폐업하는 사업장, 안내상 조건을 충족하는 휴업 사업장, 근로자가 없는 경우 등 |
| 신고 의무자 | 사업장의 사용자 |
| 폐업·휴업 사유의 신고기한 | 사유가 발생한 날이 속한 달의 다음 달 15일까지 |
| 안내 서류 | 사업장 탈퇴신고서, 휴업(폐업)사실증명원 사본. 공단 확인이 가능한 경우 증명원 생략 가능 |
| 탈퇴일 | 원칙적으로 증명원상 휴·폐업일을 기준으로 하되 실제 사실과 다르면 공단 확인 대상 |

근거: [국민연금공단 사업장의 탈퇴 안내](https://www.nps.or.kr/pnsinfo/ntpsklg/getOHAF0006M0.do?menuId=MN24001107&tab=tab10).

**이 출처 하나로 건강보험·고용보험·산재보험까지 동일한 기한·서류를 갖는다고 판단하지 않는다.**
사업장 단위 탈퇴·소멸과 근로자별 자격상실도 구분해 확인한다.
나머지 보험은 실제 가입 관계와 각 공단의 공식 안내를 추가 검수한 뒤 적용한다.
현재 직원 수가 0명이라는 사실만으로 과거 가입 관계까지 정리됐다고 보지 않는다.

## 6. Case에서의 순서와 완료 확인

아래는 공식 안내를 바탕으로 **서비스에서 확인할 관계를 정리한 해석**이다.
검수·공동 계약 없이 `STEP_DEPENDENCY`의 확정 레코드로 사용하지 않는다.

| 확인할 관계 | 취급 |
|---|---|
| 원상복구 범위 확인 → 실제 철거·점포 반환 준비 | 범위가 미확정이면 먼저 사용자 확인. 법률상 모든 철거가 의무라고 간주하지 않음 |
| 지원 검토 → 철거 증빙·신청 순서 확인 | 지원을 검토하는 경우에만 확인. 사전 승인 필수 여부는 해당 공고에 따름 |
| 사업자등록 신고 ↔ 식품영업 신고 | 통합 접수 가능성을 고려. 일률적인 선후 관계 없음 |
| 실제 폐업일 → 폐업분 부가세 기한 확인 | 예정일을 기준일로 대체하지 않음 |
| 근로관계 종료·가입 관계 → 임금 정산·보험 확인 | 직원별 퇴직일과 사업장 폐업일을 구분. 다른 절차와 병행 가능 |
| 기관 접수 → 해당 절차 완료 확인 | 신청했다는 말만으로 승인·납부·보증금 반환·Case 전체 완료를 추론하지 않음 |

사용자가 실행 결과를 입력하면 어느 절차의 어떤 결과인지 확인하고, 기존 Case와 충돌하면
사용자 확인 전 자동 덮어쓰기를 하지 않는다. 적용 대상인지 모르면 `UNKNOWN`으로 유지한다.
진행상태 저장에는 기존 `NOT_STARTED` / `IN_PROGRESS` / `COMPLETED`만 사용한다.
문서에서 언급한 ‘추가 확인 필요’를 임의의 DB 상태 값으로 추가하지 않는다.

## 7. 현재 구현과 문서의 연결

2026-09-20에 읽은 [절차 스냅샷](../../backend/app/agent/procedure_tool/data/reviewed-procedures.ko-KR.json)의
코드는 다음과 같다. 스냅샷의 식별자는 실제 DB ID로 사용하지 않는다.

| 기존 `step_code` | 이 문서의 관련 내용 | 현재 확보한 절차 스냅샷 |
|---|---|---|
| `CONFIRM_RESTORATION_SCOPE` | 임대인과 원상복구 범위 확인 | 해당 공식 원문 레코드 없음 |
| `CHECK_DEMOLITION_SUPPORT` | 철거 전 지원조건 확인 | 지원 카탈로그 경로의 별도 검수 필요 |
| `FILE_TAX_BUSINESS_CLOSURE` | 사업자등록 폐업신고 | `TAX_BUSINESS_CLOSURE` |
| `FILE_FOOD_SERVICE_CLOSURE` | 식품영업 폐업신고 | `FOOD_SERVICE_CLOSURE` |
| `REPORT_WORKPLACE_INSURANCE_CLOSURE` | 사회보험 정리 확인 | `WORKPLACE_INSURANCE_CLOSURE` — 원문은 국민연금 범위 |

현재 스냅샷 3건은 `reviewed_by`와 `reviewed_at`이 비어 있다.
이 문서에서 공식 원문을 열람한 사실로 사람 검수를 대신하거나 `CURRENT`로 바꾸지 않는다.
또한 부가세·종합소득세·노무 정산을 다뤘다고 새 절차 코드가 등록된 것으로 보지 않는다.

물리 스키마는 [schema_table.md](../schema/schema_table.md)를 따른다.
예를 들어 이 문서에서 필요한 실제 폐업일·퇴직일을 설명해도 CASE 컬럼이나 API 필드를 임의로 추가하지 않는다.
저장할 곳과 전달 계약이 정해지지 않은 사실은 AI·BE 협의 대상으로 남긴다.
공식 문서 근거는 기존 `EVIDENCE`의 출처·발췌·수집시각·최신성 등의 계약에 맞춰 다루고,
새 테이블·새 enum·암묵적인 근거 연결 규칙을 이 문서로 만들지 않는다.

## 8. 출처 검수 시 남아 있는 확인

- 위에 인용한 국세청·생활법령정보·국민연금공단·고용노동부·기업마당의 관련 본문을 열람했다.
  원문 게시일을 확인하지 못한 경우 열람일을 게시일이나 법령 시행일로 대체하지 않는다.
- 국가법령정보센터의 직접 조문 페이지는 이번 조회에서 일부 본문 추출이 되지 않았다.
  법률 요약에는 열람 가능한 공식 기관 안내를 사용했고, 개별 사건의 최신 적용 법령 검수는 별도로 남긴다.
- 기업마당의 위 공고는 2026-01-21 게시 원공고다. 희망리턴패키지 사이트의 수정 공고는
  검색 결과에서 발견했으나 직접 상세 조회에서 오류가 발생했다. 검색 결과를 본문 근거로 승격하지 않았으며,
  **최신 수정 조건·첨부·접수 및 예산 잔여 상태는 이 문서에서 검증하지 않았다.**
- 건강보험·고용보험·산재보험의 각각의 탈퇴·소멸·자격상실 및 정산 기한, 지자체별 추가 민원,
  개별 지원사업의 지급 요건은 추가 공식 자료 검수가 필요하다.
- 검수된 원문을 실제 요청 경로에 반영하는 절차는 [절차 지식 갱신](./procedure-knowledge.md),
  수집 범위와 네트워크 경계는 [공식 데이터 출처](./official-data-sources.md)를 따른다.
