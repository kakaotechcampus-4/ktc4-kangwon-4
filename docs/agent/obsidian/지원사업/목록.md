## 수집 범위

2026-09-21 재수집에서 검색어를 3개에서 10개로 늘렸습니다. 늘린 7개는 지어낸 말이 아니라
**이미 수집한 공고가 스스로 달고 있는 해시태그**입니다. 세 요청이 실패하던 문제도 함께
고쳤습니다(아래 참고).

| 검색어 | API 후보 수 | 더 남아 있음 |
|---|---|---|
| 폐업 | 8 | **예** |
| 점포철거비 | 1 | 아니요 |
| 폐업 + 재창업 | 8 | **예** |
| 사업정리 | 4 | 아니요 |
| 폐업소상공인 | 4 | 아니요 |

열 번의 요청 모두 HTTP 200이었습니다. 원시 후보 36건(중복 포함)에서 제목 필터와 외부 공고 ID
중복 제거를 거쳐 **9건**을 보존했습니다. 지원자격으로 거른 결과가 아닙니다.

**"더 남아 있음"이 '예'인 줄은 API가 "요청한 8건보다 많다"고 답했다는 뜻입니다.**
즉 `폐업`과 `폐업 + 재창업`에는 아직 가져오지 않은 공고가 남아 있습니다. 한 번에 더 많이
요청하면 공고 하나가 형식 검사에 걸릴 때 그 검색어 전체를 잃기 때문에, 요청 건수를 올리는
대신 검색어를 늘리는 쪽을 택했습니다. 페이지 넘기기는 아직 구현하지 않았습니다.

**이번에 고친 것:** `폐업소상공인`·`폐업예정소상공인`·`희망리턴패키지` 세 검색어가 계속
실패하고 있었습니다. 원인은 공고 하나(`PBLN_000000000117673`)의 신청 홈페이지 주소가
`https://www.sbiz24.kr/#/pbanc/591`처럼 `#` 뒤에 경로를 두는 형태인데, 주소 검사가 `#`를
무조건 거부했기 때문입니다. 소상공인24의 정상적인 주소이고 `#`를 잘라내면 사용자를 엉뚱한
페이지로 보내게 되므로, **기관 자체 신청 주소에 한해** `#`를 허용하고 그대로 보존하도록
고쳤습니다. 기업마당 자체 주소는 형식이 정해져 있어 그대로 엄격하게 둡니다.

재실행해도 기존 노트를 덮어쓰지 않습니다. 같은 공고가 여러 응답에 있으면 처음 기록한 자료를
유지하며, 변경된 내용·수집시각은 자동 갱신하지 않습니다. 이번 실행에서도 기존 7건은 그대로
