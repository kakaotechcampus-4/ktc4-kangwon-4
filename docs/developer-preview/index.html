결과 알려주기

현실에서 확인한 결과를 받아 가게 상태와 다음 할 일을 다시 검토합니다.

구현됨개인 카페 · 원상복구 답변 예시
이해하기REST API에러 코드

이 기능이 필요한 이유

사장님의 할 일은 가게 상황에 따라 달라집니다. 임대인에게 확인한 답을 리본에 알려주면, 이전에 모르던 사실을 채우고 지금 할 일을 다시 검토할 수 있습니다.

대표 사용 흐름

  1. 임대인에게 확인하기

    홈에서 원상복구 범위와 철거 필요 여부를 확인할 질문을 봅니다.

  2. 받은 답 알려주기

    서버가 허용한 보기로 고르거나, 임대인에게 들은 말을 직접 적습니다.

  3. 반영 결과 확인하기

    바뀐 가게 정보와 다음 할 일을 보고, 다르게 이해했으면 바로잡습니다.

입력에 따른 처리

입력 상황서비스 동작사용자에게 보이는 것
새 사실이 확인됨검수 후 상태 저장바뀐 내용과 다음 할 일
일부 복구지만 구체 범위가 없음상세 내용 되묻기추가 질문
기존 확정값과 다른 사실 후보자동 덮어쓰기 중단기존 값과 새 값 선택
같은 내용을 다시 알려줌변경 없음으로 구분바뀐 내용이 없다는 안내
중요 · 반영 전 승인과 구분정상 반영 결과의 [맞아요]는 저장 승인 버튼이 아닙니다. 서버가 반영한 내용을 보여주는 단계이며, 다르게 이해했으면 다시 적어 바로잡습니다.

테스트 케이스

정상 · 원상복구 범위와 철거 여부를 모두 선택

최신 판단 번호와 답을 전송하면 새 접수 번호를 받습니다. 처리가 끝난 뒤에 반영 결과를 조회합니다.

경계 · 일부 복구를 고르고 상세 범위는 알리지 않음

어느 부분인지 정해졌다고 추측하지 않고, 구체적인 원상복구 범위를 다시 질문해야 합니다.

예외 · 기존 확정값과 새 답변이 충돌

사용자 선택 전에 Case의 기존 값을 덮어쓰면 안 됩니다. 유효한 선택 후 재판단과 검수를 수행합니다.

동시성 · 지난 판단 번호로 보내거나 두 번 제출

현재 진행 상태를 확인하고 받을 수 없는 요청은 409로 거부해야 합니다.

결과 알려주기 REST API

실행 결과를 접수하고 판단 결과를 조회합니다.

Backend 경로 기준예제 응답은 설명용 값입니다.
이해하기REST API에러 코드

결과 접수

메서드URL인증 방식
POST/cases/results리본 액세스 토큰

요구 사항 로그인과 Case 생성, 최신 판단 번호가 필요합니다. 먼저 GET /cases/results로 현재 입력 가능한 종류와 case_history_id를 확인합니다.

참고 · 리본과 카카오의 인증 헤더 구분이 API는 리본 자체 JWT를 Access-Token 헤더로 받습니다. 카카오 액세스 토큰을 직접 보내는 API가 아닙니다. FE 프록시를 거치면 경로 앞에 /api가 붙습니다.

카카오 로그인

공식 가이드와 리본의 구현을 연결해 인증 흐름을 확인합니다.

현재 사용 중REST API 방식 · 자체 JWT 발급

리본에서의 동작 흐름

로그인 버튼
state 생성→카카오 인증
사용자 동의→콜백 검증
code 전달→BE 토큰 교환
회원 확인→리본 JWT 발급
Case 진입

FE가 OAuth state를 만들어 콜백에서 한 번 검증합니다. BE는 받은 code로 카카오 토큰을 교환하고 사용자 정보를 조회합니다. 이후 리본의 회원을 확인하고 자체 Access·Refresh JWT를 발급합니다.

설정과 구현 위치

구분리본에서 확인할 것
카카오 앱 설정로그인 사용 설정, Redirect URI, 필요한 동의항목
서버 설정KAKAO_CLIENT_ID · KAKAO_CLIENT_SECRET · KAKAO_REDIRECT_URI
공개 FE 환경변수에 비밀값을 넣지 않음
FELoginPage · LoginCallbackPage · lib/auth.ts
BErouters/auth.py · services/auth.py
주의 · 두 종류의 액세스 토큰카카오 사용자 정보 조회에는 카카오 토큰을 사용하고, 리본의 Case API에는 리본 JWT를 사용합니다. 공식 문서의 인증 예제를 리본 API 요청에 그대로 붙이지 않습니다.

확인할 테스트

state 누락·불일치·재사용을 거부하는가

콜백이 현재 탭에서 시작한 로그인인지 확인해야 합니다. state는 성공·실패와 관계없이 한 번만 사용합니다.

배포·로컬 Redirect URI가 일치하는가

카카오 앱 설정, 서버 환경변수, 실제 콜백 주소를 맞춥니다. 미리보기 가짜 로그인은 실제 카카오 연동 성공의 증거가 아닙니다.

여러 401 응답에 재발급이 중복되지 않는가

동일한 Refresh 토큰의 재발급은 공유하고, 뒤늦은 응답이 로그아웃이나 새 로그인을 되살리지 않아야 합니다.
