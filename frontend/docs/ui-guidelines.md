# UI 가이드라인

RE:BORN 프론트엔드의 시각·상호작용·접근성 기준.

토큰은 **Tailwind 기본 스케일을 그대로 쓴다.** 커스텀 `@theme`을 만들지 않는다.
아래 표는 hex가 아니라 클래스 이름으로 적는다 — 코드에 그대로 옮겨 쓰기 위해서다.

---

## 색

### 의미별

Case의 상태를 나타내는 다섯 가지. 카드·배지·배너에 세트로 쓴다.

| 의미 | 텍스트 | 배경 | 테두리 |
|---|---|---|---|
| **확인됨 · 해결 · 완료** | `text-emerald-800` | `bg-emerald-50` | `border-emerald-200` |
| **미확인 · Blocker · 주의** | `text-amber-800` | `bg-amber-50` | `border-amber-200` |
| **정보 · 후보 · 확인 요청** | `text-blue-800` | `bg-blue-50` | `border-blue-200` |
| **마감 임박 · 오류** | `text-red-700` | `bg-red-50` | `border-red-200` |
| **대기 · 중립 · 해당 없음** | `text-gray-600` | `bg-gray-100` | `border-gray-200` |

### 기본

| 역할 | 클래스 |
|---|---|
| 화면 배경 | `bg-gray-50` |
| 카드 배경 | `bg-white` |
| 제목 · 강조 텍스트 | `text-gray-900` |
| 본문 | `text-gray-600` |
| 보조 설명 | `text-gray-500` |
| 비활성 · 플레이스홀더 | `text-gray-400` |
| 테두리 | `border-gray-200` |
| 입력 필드 테두리 | `border-gray-300` |
| 구분선 | `border-gray-100` |
| **주요 버튼 · 링크** | `bg-blue-600` / `text-blue-600` |
| **Next Action 카드** | `bg-gray-900 text-white` |

> **파랑이 두 가지인 이유** — `blue-600`은 버튼 배경과 링크처럼 **누르는 것**에 쓴다.
> `blue-800`은 연한 파랑 배경(`bg-blue-50`) 위에 얹는 **읽는 글씨**다. 역할이 다르다.

**Next Action 카드가 화면에서 가장 강한 요소다.** 어두운 배경은 여기에만 쓴다.

## 타이포그래피

### 폰트

**현재는 시스템 sans-serif를 쓴다.** `src/index.css`에 폰트 로딩이 없고,
Tailwind 기본 `font-sans` 스택(`-apple-system`, `Segoe UI`, `Roboto` …)이 그대로 적용된다.

**웹폰트 도입 예정이며 후보는 아직 미정이다.**
도입할 때 한글 서브셋과 로딩 성능을 함께 검토하고 이 문서를 고친다.

weight는 **`font-normal`과 `font-bold`만** 쓴다.

### 크기

| 클래스 | 크기 | 용도 |
|---|---|---|
| `text-xs` | 12px | 배지, 라벨 |
| `text-sm` | 14px | 보조 설명, 각주 |
| `text-base` | 16px | **본문**, 카드 제목, 버튼 |
| `text-lg` | 18px | 화면 제목 |
| **`text-2xl`** | **24px** | **Next Action 본문** — 화면에서 가장 큰 글씨 |

`leading-relaxed`(본문) / `leading-snug`(제목).

> **본문이 16px인 이유** — 중장년 사용자가 주 타깃이라 14px은 작다.
> 그리고 iOS Safari는 입력 필드의 폰트가 16px 미만이면 포커스할 때 화면을 자동 확대한다.
> Case 생성처럼 입력이 있는 화면에서 실제로 거슬린다.
>
> `text-xl`(20px)을 건너뛴 것은 의도적이다. 화면 제목(18px)과 Next Action(24px) 사이를
> 벌려서 Next Action이 확실히 도드라지게 한다.

## 간격과 모서리

| | 클래스 |
|---|---|
| 화면 좌우 여백 | `px-4` |
| 카드 안쪽 여백 | `p-4` |
| Next Action 카드 안쪽 여백 | `p-5` |
| 카드 사이 간격 | `gap-3` |
| 모서리 — 버튼, 배너, 작은 요소 | `rounded-xl` |
| 모서리 — 카드 | `rounded-2xl` |
| 모서리 — 배지 | `rounded-full` |

세 가지 반지름만 쓴다. 값을 늘리지 않는다.

## 모바일 우선

- **기준 폭 375px.** 이 폭에서 먼저 만들고 넓은 화면을 나중에 대응한다
- 세로 스크롤만. 가로 스크롤이 생기면 버그다
- 터치 영역은 최소 44px

화면 구성(하단 탭 개수 등)은 디자인 규칙이 아니라 제품 명세다.
확정되면 루트 `docs/hero-scenario.md`에 적는다.

## 접근성

중장년 사용자가 주 타깃이라 선택이 아니라 요구사항이다.

- **색상만으로 상태를 구분하지 않는다.** 색에는 반드시 **텍스트 라벨**을 함께 두고,
  아이콘은 보조 수단으로만 쓴다. `bg-amber-50` 하나로 "미확인"을 전달하면 안 된다
- **상태 아이콘은 보이는 텍스트 라벨과 함께 쓴다.** `✅`·`❓` 만으로 상태를 전달하지 않는다
- **텍스트 옆의 장식용 아이콘에는 `aria-hidden="true"` 를 준다.**
  옆에 "미확인"이라는 글자가 이미 있는데 아이콘에도 이름을 붙이면 스크린리더가 같은 뜻을 두 번 읽는다
- **아이콘만 있는 버튼에는 접근 가능한 이름을 준다** (`aria-label` 또는 시각적으로 숨긴 텍스트)
- **키보드 포커스를 표시한다.** `focus-visible` 스타일을 지우지 않는다
- **입력 필드에 항상 라벨을 준다.** 플레이스홀더로 라벨을 대신하지 않는다
- **오류 메시지를 해당 입력과 연결한다** (`aria-describedby`)
- **터치 영역 최소 44px**

## 이 제품의 UI 기준

일반적인 UI 가이드가 아니라 RE:BORN이라서 지켜야 하는 것들이다.

### N1 · 별도 학습 없이 이해된다

중장년 사용자를 기준으로 판단한다.
검증 기준은 *"제시된 행동을 자기 말로 다시 설명할 수 있는가"* 다.
설명이 필요한 UI는 실패한 UI다.

### N2 · 강하게 강조하는 것은 하나

| 요소 | 취급 |
|---|---|
| **Next Action** | 화면에서 유일하게 강하게 강조한다 (`bg-gray-900`, `text-2xl`) |
| **Blocker** | 왜 막혔는지 설명하는 **보조 정보**. amber 카드로 두되 Next Action보다 약하게 |
| **주요 버튼** | 화면당 하나. 배치는 아래 참조 |
| 나머지 미확인 항목 | `나중에 확인할 것` 처럼 접어둔다 |

Blocker와 Next Action이 서로 시선을 뺏으면 안 된다.

#### 주요 버튼을 어디에 두나

| 화면 | 주요 버튼 |
|---|---|
| **Next Action 카드가 있는 화면** | 카드 **안의** 실행 버튼이 그 화면의 주요 버튼이다. 카드 밖에 또 두지 않는다 |
| **생성·입력 화면** (카드 없음) | 폼의 제출 버튼 하나 |

선택지가 나란히 놓일 때는 **주요(primary) 스타일이 하나**고 나머지는 보조(secondary)다.
`맞아요` / `수정할게요` 처럼 두 버튼이 함께 있으면 앞쪽만 채움 스타일로 둔다.

### N3 · 전문용어를 그대로 노출하지 않는다

행정·법률·세무 용어를 화면에 그대로 쓰지 않는다. 불가피하면 일반 표현을 함께 준다.
검증 기준은 *"사용자가 뜻을 되물은 전문용어가 세션당 2회 이하"* 다.

### 확인 다이얼로그를 남발하지 않는다

되돌릴 수 없는 행동이 아니면 **경고성 확인 다이얼로그**를 두지 않는다.
현재 MVP 루프 안에서 되돌릴 수 없는 것은 **전문가 자료 전달 하나뿐**이다.

단, Case 상태를 바꾸기 전에 후보(candidate)를 검토·확정하는 화면은 여기 해당하지 않는다.
그건 경고가 아니라 **데이터 검증 절차**다. 모달이 아니라 화면 본문에서 처리한다.

### 재촉하지 않는다

사용자가 아직 확인하지 못한 상태는 정상이다.
폐업 결심 후 실제 폐업까지 평균 7.7개월이 걸린다
(중소벤처기업부 「2026 폐업 소상공인 실태조사」).
절차가 장기간 이어질 수 있으므로 처리 중이거나 아직 확인하지 못한 상태를 비정상으로 간주해 재촉하지 않는다.

Case를 그대로 유지하고, **공식 기한이 있는 항목만** 임박 상태로 강조한다.
기준 일수는 서버가 판단한다. 프론트에 D-day 숫자를 두지 않는다.

### 출처를 함께 표시한다

추출된 사실에는 어디서 온 값인지 태그를 붙인다.

| 태그 | 화면 표시 |
|---|---|
| 사용자가 직접 말함 | 그대로 표시 |
| 문서에서 추출 | 원문과 함께 표시 |
| 모델 추론 | 추정임을 명시 |

**태그에 따라 확인 단계를 건너뛸지는 아직 미정이다.**
확정 전까지는 출처와 무관하게 모든 후보에 확인을 받는다 (`CLAUDE.md` 규칙 3).

어느 경우든 **서버가 저장 성공을 응답한 뒤에** Case의 확정 값을 바꾼다.
오류 응답에는 확정 값을 바꾸지 않는다.

### 미확인은 미확인으로 보여준다

`UNKNOWN`을 빈 값으로 숨기지 않는다.
확인된 값과 시각적으로 구분하되, 색만으로 구분하지 않는다 — 아이콘과 텍스트를 함께 쓴다.

### 쓰지 않는 표현

| 쓰지 않음 | 대신 |
|---|---|
| 추천 | 조건에 해당함 |
| 지원 가능 · 지원금 수령 확정 | 검토 대상 · 추가 확인 필요 |
| Task | 다음 행동 |
