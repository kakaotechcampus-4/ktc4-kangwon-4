# RE:BORN Frontend

폐업을 결심한 임차형 소상공인의 Closure Case를 관리하는 Agent 서비스.
**FE는 서버가 판단한 Blocker와 Next Action을 보여주는 표면이다.**

> 팀 공통 규칙(하지 않는 것 · 역할 경계 · 개인정보 · 용어)은 레포 루트 `CLAUDE.md`에 둔다.
> 아직 작성 전이라 아래 "핵심 루프"를 임시로 여기 둔다. 루트가 생기면 옮긴다.

## 핵심 루프

```
Case 생성 → Blocker 1개 판정 → Next Action 1개 제시
  → 사용자가 현실에서 실행 → 결과 입력 → Case 상태 변경 → 재계획 → (반복)
```

화면은 이 루프의 한 단계를 보여주는 것이다.

## 스택

- **TypeScript + React 19**, 빌드는 **Vite**
- 스타일 **Tailwind CSS 4** — `tailwind.config.js`와 PostCSS 설정이 없다.
  `@tailwindcss/vite` 플러그인과 `src/index.css`의 `@import "tailwindcss";` 로 동작한다.
  3버전 방식(`tailwind.config.js`, `@tailwind base;`)을 쓰지 않는다
- 통신 **Fetch API** — axios 등 HTTP 클라이언트를 추가하지 않는다
- 상태관리는 **React 내장**(`useState` / `useContext`). 외부 상태 라이브러리를 도입하지 않는다
- **Mobile-first** 반응형. 기준 폭 375px

현재 설치된 패키지와 버전, 실행 방법은 `README.md`를 본다.

## 규칙

1. **Blocker와 Next Action을 프론트에서 계산하지 않는다.**
   선행조건·지원자격·우선순위 판단 로직을 구현하지 않고 서버 응답을 표시한다.
   "이 조건이면 이게 먼저다" 같은 판단이 프론트 코드에 들어오면 잘못된 것이다.

2. **서버가 확정 상태로 저장한 값만 Case UI에 반영한다.**
   요청이 성공하기 전에 화면 값을 미리 바꾸지 않는다(낙관적 업데이트 금지).
   후보(candidate)와 `CONFLICT`는 확정 상태로 그리지 않는다.

3. **후보와 충돌 결과는 사용자 확인을 거친 뒤 반영한다.**
   확인 전에는 Case 화면의 값을 바꾸지 않고, 기존 값과 새 값을 함께 보여준다.
   *(어떤 입력까지 확인을 받을지는 아직 팀에서 확정되지 않았다. 확정 전까지는
   위와 같이 보수적으로 — 모든 후보에 확인을 받는 쪽으로 — 처리한다.)*

4. **`result` 6종을 전부 분기한다. 미처리 분기를 남기지 않는다.**
   `UPDATED` / `NO_CHANGE` / `NEEDS_MORE_INFO` / `CONFLICT` / `REPLAN_FAILED` / `CASE_NOT_FOUND`
   응답 타입은 discriminated union으로 정의해 컴파일 단계에서 누락이 잡히게 한다.

5. **한 화면에서 강하게 강조하는 것은 Next Action 하나다.**
   Blocker는 그 이유를 설명하는 보조 정보로 둔다. 주요 버튼도 화면당 하나다.
   나머지 미확인 항목은 접거나 약하게 표시한다.

6. **서버가 확정하지 않은 값을 확정된 것처럼 표시하지 않는다.**
   `UNKNOWN`은 미확인으로 보여준다. 빈 값으로 숨기지 않는다.

7. **업무 판단에 해당하는 날짜·금액·기간을 프론트에서 산출하거나 하드코딩하지 않는다.**
   지원 자격, 마감 임박 여부, 지원 금액, 남은 기간 판단이 여기 해당한다.
   서버가 준 값만 쓰고, 없으면 "확인 필요"로 표시한다.
   D-day 기준일수 같은 숫자를 프론트에 두지 않는다.

   **서버 값을 화면 표시 형식으로 바꾸는 것은 허용한다.**
   `Intl.NumberFormat`으로 `1500000` 을 `1,500,000원` 으로, `Intl.DateTimeFormat`으로
   `2026-09-30` 을 `9월 30일` 로 바꾸는 것은 판단이 아니라 표시다.

8. **정상 화면과 예외 화면을 같은 작업 단위에서 만든다.**
   정상 화면만 먼저 만들고 예외를 나중에 붙이지 않는다.
   어떤 예외가 있는지는 루트 `docs/hero-scenario.md`에 정리한다(작성 예정).

9. **확정되지 않은 API 필드를 임의로 타입에 추가하지 않는다.**
   optional로 만들어 두면 실제 응답이 비어 있어도 조용히 넘어가 버그를 숨긴다.
   화면 구현에 그 필드가 필요하면 `// TODO` 를 남기고 **계약 확정을 요청한다.**
