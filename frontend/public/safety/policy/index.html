교육 프로젝트로 만든 서비스예요

리본은 카카오테크 캠퍼스 교육 과정에서 RE:BORN 팀이 만든 프로젝트이며, 영업을 하는 서비스가 아니에요. 별도의 이용약관은 두지 않고 이 안내로 대신해요. 안내 내용은 정확하게 쓰려고 노력하지만 지원금·법률·세무 판단을 보증하지 않아요.

실제 서류 대신 연습용 자료로 이용해 주세요. 아래에 적은 것처럼 아직 회원 탈퇴와 자료 영구 삭제 기능이 없어요.

01

받는 정보

카카오 로그인 — 카카오 회원번호와 닉네임만 받아요. 이메일·전화번호·생일·프로필 사진은 요청하지 않아요. 카카오가 준 접속 열쇠(토큰)는 회원 확인에 한 번 쓰고 저장하지 않아요.

상황 진단과 결과 알려주기 — 가게 이름, 업종, 직원 수와 예전 직원·사업장 보험 이력, 대출·서비스 계약 여부, 임대와 원상복구 상황, 폐업 예정일과 폐업일, 폐업 신고에 쓰는 가게 주소, 보증금 반환 결과를 받아요. 결과를 알릴 때 적은 글은 원문 그대로 저장해요.

서류함 — 올린 PDF·사진에서 쪽 이미지를 만들어 보관해요. 올린 파일 그대로는 저장하지 않아요. 파일 이름, 같은 파일인지 알아보는 값(SHA-256), 서류에서 읽은 값(상호·공급자·받는 사람·예금주·금액·날짜 등)과 사장님이 확인한 값을 함께 보관해요.

정산 서류 점검 — 점검할 때 적은 가게 이름, 신청인 이름, 실제 폐업일을 점검 결과와 함께 보관해요.

02

정보를 쓰는 곳

회원 확인, 지금 먼저 할 일과 폐업 로드맵 안내, 서류 종류·값 읽기와 정산 서류 점검, 제출 파일 만들기, 작업 기록 보여 주기에만 써요. 광고나 마케팅에는 쓰지 않아요.

03

보관과 삭제

가게 정보·판단 기록·서류 목록과 점검 결과는 데이터베이스에, 서류의 쪽 이미지와 읽은 값은 서버의 파일 저장소에 보관해요. 정해 둔 자동 파기 기한은 없어요.

지금 없는 기능 — 회원 탈퇴와 Case 삭제 기능이 없어요. 서류함의 삭제는 목록에서 빼고 점검을 초기화하는 것이며, 저장된 파일까지 지우지는 않아요. 서버를 새로 배포할 때마다 데이터베이스와 서류 파일의 백업을 만들고, 이 백업을 지우는 기한도 아직 정하지 않았어요.

로그아웃 — 서버에 저장된 로그인 유지용 열쇠(Refresh 토큰)를 지워요.

04

밖으로 보내는 곳

AI 모델 (Elice 모델 API) — 서류를 읽고 상황을 판단할 때 가린 자료를 보내요. 주민등록번호, 사업자·계좌·전화번호 같은 식별번호와 이메일은 가려서 보내지만, 서류 속 이름·금액·날짜는 가리지 않고 보내요. 적어 주신 글도 규칙으로 일부를 가린 사본을 보내요. 글자 인식(OCR)은 리본 서버 안에서 해요.

서비스를 돌리는 곳 — 화면은 Vercel에서 내려받고, 서버로 가는 요청도 Vercel을 거쳐 리본 서버(AWS)로 가요. 로그인은 카카오를 쓰고, 주소 검색은 다음(Daum) 우편번호 서비스를 브라우저에서 불러와요.

설정했을 때만 쓰는 도구 — 처리 기록 도구(Langfuse)에는 모델·처리 시간·토큰 수 같은 기록만 보내고 입력 원문과 서류 내용은 보내지 않아요. 서버 오류 알림(Discord)에는 오류 종류와 위치, Case 번호 같은 내부 번호만 보내고 입력 글과 서류 값은 보내지 않아요.

05

브라우저에 남는 것

로그인 열쇠와 진행 중인 진단 답은 브라우저의 세션 저장소(sessionStorage)에 두며, 탭을 닫으면 사라져요. 쿠키와 방문 분석 도구는 쓰지 않아요. 개발 문서는 최근 본 문서의 제목과 주소만 이 브라우저에 저장해요.

06

열람·삭제 요청

저장된 내 정보를 보고 싶거나 지우고 싶으면 RE:BORN 팀 저장소의 이슈로 요청해 주세요. 이슈는 누구나 볼 수 있으니 가게 정보나 서류 내용은 적지 말고 요청만 남겨 주세요. 본인 확인과 처리 방법은 팀이 이슈에서 안내해요. 앱 안에 삭제 기능이 없어서 팀이 직접 확인하고 처리해요. 가게 정보는 앱의 내 정보 화면에서 볼 수 있어요.
