01

필요한 사실을 중심으로 알려주세요

가게의 상황과 진행을 이해하는 데 필요한 내용을 적어 주세요. 다른 사람의 연락처·계좌번호·인증 정보처럼 안내에 불필요한 정보는 글에 넣지 않는 것이 좋아요. 입력 글에서 일부 식별 정보를 가리는 처리가 있어도 처음부터 필요한 정보만 전달하는 것이 중요해요.

02

가림 범위를 구분해요

자유롭게 적은 글에서는 일부 식별번호·연락처·이메일·주소와 이름임을 명시한 일부 표현 등을 규칙으로 가려요. 모든 문장 속 개인정보를 탐지하는 것은 아니에요. 결과·충돌 확인 화면에도 [주소] 같은 가림 표시가 그대로 보이고 원래 글자로 되돌리지 않아요. 적어 주신 원문은 다시 판단하거나 충돌을 확인할 때 쓰려고 서버에만 남겨요. 문서의 AI 판독용 가림과 기관 제출용 가림은 목적이 달라요. 현재 제출용 파일은 주민등록번호 뒷자리를 가리며, 계좌·사업자번호까지 모두 숨기는 방식은 아니에요.

03

다른 가게의 자료와 분리해요

회원의 Case에 속한 서류와 이력만 요청할 수 있도록 서버에서 소유권을 확인해요. 다운로드할 때도 현재 서류·점검 결과·파일 상태가 맞는지 대조해요. 이 가이드에 나온 화면과 사례에는 실제 운영 이용자 자료를 사용하지 않아요.

04

삭제의 의미도 정확히 알려요

가게 상태·이력과 서류 목록·읽어낸 값·점검 결과는 데이터베이스에, 처리한 PDF와 분석 캐시 등은 서버의 파일 저장소에 보관해요. 서류를 읽는 사이 삭제하거나 직접 확인한 내용이 이전 값으로 돌아가지 않도록 최신 목록과 대조해 저장해요. 현재 서류함 삭제는 목록 제외와 점검 초기화이며 저장된 모든 파일의 영구 삭제를 뜻하지 않아요. 이 안내만으로 별도의 자동 파기 기한이나 회원 탈퇴 기능을 약속하지 않아요.

05

처리 기록과 원문을 구분해요

추적 기능을 설정한 경우 모델 사용량·처리 시간·상태, 가게 자료를 연결하는 내부 번호와 검수 이슈의 종류 등을 기록해요. 입력 원문·OCR 텍스트·검수의 자유 설명을 추적 도구로 전송하지 않도록 구성해요. 이는 서류 판독에 필요한 모델 처리 자체가 없다는 뜻은 아니에요. 모델 판독에 사용하는 자료와 개발용 처리 기록을 구분해서 설명해요.

06

내려받은 파일은 공유 전에 확인해 주세요

파일 안의 이름·계좌·사업자번호·날짜와 가림 범위를 직접 확인해 주세요. 제출처가 요청하는 자료만 전달하고, ZIP 다운로드를 기관 제출 완료로 오해하지 않도록 해요.
