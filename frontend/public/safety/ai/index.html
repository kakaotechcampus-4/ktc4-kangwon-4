AI를 사용하는 방식

AI가 제안하고,
확인과 검수를 거쳐요.

상황을 이해하는 기술과, 그 기술이 멈추고 다시 확인해야 하는 지점을 함께 알려드려요.

이 페이지에서바로 확정하지 않는 안내서류의 내용과 맞지 않는 값을 확인해요처리를 멈추는 이유도 구분해요검수에도 한계가 있어요검증 결과도 범위와 함께 공개해요
01

바로 확정하지 않는 안내

리본은 절차 근거 준비 → 입력 사실 정리 → 다음 행동 선택 → 검수의 순서로 안내를 준비해요. 확정한 상태와 다른 답변은 충돌로 다루고, 검수한 변경만 저장해요. 일부 정해진 선택형 입력과 검수는 AI 모델을 다시 부르는 대신 코드 규칙으로 처리해요.

  1. 절차의 근거와 조건 확인
  2. 사장님이 알려준 사실 정리
  3. 다음 행동 또는 추가 질문 선택
  4. 검수와 최신 상태 대조 후 반영
02

서류의 내용과 맞지 않는 값을 확인해요

문서 종류와 값을 추출한 뒤 불확실한 내용은 사장님에게 확인받아요. 서류 누락과 금액·이름·날짜의 대조는 정해진 점검 규칙을 사용해요. 서류가 달라지면 지난 점검을 그대로 통과 결과로 사용하지 않아요.

03

처리를 멈추는 이유도 구분해요

자료 속의 안전 검사 우회·정보 유출 지시나 처리할 수 없는 요청은 자동 처리를 중단할 수 있어요. 현재 위기에 대한 도움 요청으로 판정된 경우에는 기존 서류와 진행을 유지하고 공식 상담 창구를 안내해요. 단순한 읽기 실패나 일시 오류와 구분하며, 자동 감지가 모든 위험이나 맥락을 정확히 판별한다는 뜻은 아니에요.

04

검수에도 한계가 있어요

AI는 서류를 잘못 읽거나 내용을 다르게 해석할 수 있어요. 자동 검수가 정확성·최신성·기관 수리를 보장하지는 않아요. 중요한 계약 내용과 이름·금액·날짜는 원본 및 담당 기관의 최신 안내와 대조해 주세요. 현재 리본은 요청마다 새로운 웹 자료를 수집해 안내하는 방식이 아니에요.

05

검증 결과도 범위와 함께 공개해요

개발 문서에서 자동 테스트의 기준과 변경 이력을 확인할 수 있어요. 모의 응답을 사용한 테스트 통과와 실제 AI의 정확도·운영 성과는 구분해요. 실제 차단 건수나 상담 대응 실적처럼 측정하지 않은 수치를 공개 성과로 제시하지 않아요.
