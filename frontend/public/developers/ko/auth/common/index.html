카카오 로그인 이해하기

카카오 인증과 리본의 회원·JWT를 연결합니다.

코드 기준 c01bf12 · 확인 2026-11-10
이해하기설정하기REST API에러 코드

동작 흐름#

FE가 state를 생성하고 카카오로 이동합니다. 콜백에서 일회 검증한 뒤 code를 BE에 전달합니다. BE는 카카오 토큰 교환과 사용자 정보 조회를 수행하고 리본 회원을 확인해 자체 Access·Refresh JWT를 발급합니다.

  1. GET /login/form으로 인가 화면에 이동합니다.
  2. 카카오 인증 뒤 /login/callback에서 state를 확인합니다.
  3. POST /login에 code를 보냅니다.
  4. 응답 헤더에서 리본 토큰을 받습니다.
  5. Case 유무에 따라 진단 또는 홈으로 이동합니다.

두 종류의 토큰#

카카오 사용자 정보 조회에는 카카오 토큰을 사용하며 리본 API에는 자체 JWT를 Access-Token 헤더로 보냅니다. 토큰은 sessionStorage에 있고, 401이면 Refresh-Token으로 재발급을 시도합니다.

현재 저장 방식

sessionStorage는 XSS 노출을 해결하는 장치가 아닙니다. Access를 메모리에 두는 개선은 현재 코드의 후속 과제입니다.

콜백과 동시 재발급#

state는 누락·불일치·재사용을 거부하며 검증 후 폐기합니다. 같은 카카오 계정의 첫 로그인이 겹쳐 회원 생성이 경합하면 롤백 뒤 먼저 생성된 회원으로 로그인을 이어갑니다. 같은 Refresh 토큰의 동시 재발급은 공유하고, 늦은 응답이 로그아웃이나 새 로그인을 덮지 않게 합니다.

로그인 오류 구분#

카카오 토큰 교환의 잘못되거나 재사용된 인가 코드 등 4xx는 리본의 400으로, 카카오 401인 앱 키·시크릿 설정 문제와 통신·상위 서버 오류는 502로 나눕니다. 카카오 응답 본문이나 인증 비밀을 사용자 안내·로그에 그대로 남기지 않습니다.

공식 문서#

카카오 API 자체의 설정과 규격은 공식 원문을 참고하고, 이 문서에서는 리본에서 연결하는 방법을 설명합니다.
