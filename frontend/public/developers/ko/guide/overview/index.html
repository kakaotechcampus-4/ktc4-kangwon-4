서비스 이해하기

폐업을 결정한 40~50대 개인 카페 사장님의 다음 행동과 필요한 서류를 정리합니다.

코드 기준 5a8d11a · 확인 2026-11-11

리본이 해결하는 문제#

폐업을 결정한 사장님은 임대차·원상복구·직원 정산·신고에 흩어진 안내를 내 가게에 적용해, 무엇을 먼저 실행하고 어떤 결과와 서류를 남길지 직접 연결해야 합니다. 리본은 한 가게의 확인된 상태와 진행을 Case로 모으고, 지금 먼저 확인할 행동과 이유를 안내합니다. 실행 결과를 알려주면 다음 행동을 다시 검토합니다.

핵심 대상과 제공 범위#

핵심 설계 대상은 폐업 절차와 서류를 직접 챙기는 40~50대 비프랜차이즈 개인 카페 사장님입니다. 연령은 제품 설계의 초점이며 가입 제한이 아닙니다. 현재 로드맵은 개인 카페를 지원하며 프랜차이즈 카페와 일반 음식점은 지원 준비 중으로 안내합니다. 기관 신청·제출, 임대인 연락, 실제 철거는 사장님이 직접 수행합니다.

지원사업 정보

현재 MVP는 지원금 자격·금액·접수 가능 여부를 자동 확정하지 않습니다. Support Agent 구현은 남아 있지만 현재 Graph에서는 호출하지 않습니다.

대상과 화면 설계를 함께 설명하기#

40~50대 사장님이 폐업 절차를 읽고 실행하는 부담을 줄이고자 Pretendard, 홈 할 일 제목 26px, 주요 버튼 글자 18~19px·높이 56~60px, 질문을 나눠 보여주는 배치와 선택형 입력을 적용했습니다. 현재 행동과 전체 로드맵을 분리하고, 할 일의 성격에 맞는 준비·제출·처리 완료 버튼과 원상복구 진행 상태 버튼을 제공합니다. 선택형 범위의 모름과 직접 입력도 구분합니다. 최초 진단의 과거 고용·보험 이력 질문은 현재 예·아니요로 받습니다.

설계 대상과 검증

연령만으로 디지털 숙련도를 단정하지 않습니다. 현재 설명은 설계 의도와 구현 근거이며, 해당 연령대의 수요·사용성 효과를 검증했다는 뜻은 아닙니다.

40~50대를 고려한 UI/UX와 확인 과제 ↗

우리가 강조하는 연결#

리본의 핵심은 정보를 많이 보여주는 데서 끝나지 않고, 내 가게의 확인된 사실 → 지금 할 일 하나 → 현실에서 실행한 결과 → 검수와 다음 안내를 연결하는 것입니다. 준비를 확인한 것과 실제 철거를 끝낸 것은 나눠 기록하며, 등록된 절차 안내가 끝나면 새로운 할 일을 억지로 만들지 않습니다. 종료 뒤에도 서류함과 기록에서 남은 자료를 확인합니다.

기술 구성과 데이터 흐름 ↗절차 안내 종료의 의미 ↗

운영철학과 안심 이용#

사장님의 선택을 존중하고 확인한 정보로 안내하며, 서류 보호·AI 검수·정정과 복구 방법을 이용자 눈높이로 설명합니다.

리본 안심가이드 ↗운영철학 ↗

서비스 흐름#

정해진 체크리스트를 한 번 보여주는 대신, 현실에서 알아본 내용을 받아 상태와 다음 행동을 갱신합니다.

  1. 로그인하고 가게 상황을 진단합니다.
  2. 홈에서 지금 할 일과 실제로 물어볼 말을 확인합니다.
  3. 현실에서 실행한 결과를 보기 또는 글로 알려줍니다.
  4. 새 사실·추가 질문·충돌을 검수하고 저장합니다.
  5. 로드맵, 서류와 기록을 보며 다음 행동을 이어갑니다.

대표 시연#

임대인에게 원상복구 범위를 확인한 뒤, 카운터·싱크대·간판만 철거하면 된다는 답을 입력합니다. 리본이 이해한 범위와 철거 필요 여부를 확인하고, 정보가 부족하면 더 답하거나 다르게 이해했으면 바로잡습니다.
