서류함과 정산 점검

사진과 PDF를 모아 종류·값을 확인하고 정산 서류를 대조합니다.

코드 기준 5a8d11a · 확인 2026-11-11
이해하기REST API에러 코드

문서 처리 흐름#

업로드와 점검은 별도 기능입니다. 올린 파일이 있다는 사실만으로 점검 통과나 기관 제출이 되지 않습니다.

  1. PDF·PNG·JPG/JPEG를 한 장씩 올립니다.
  2. 로컬 OCR과 가린 자료의 모델 판독으로 종류와 값을 읽습니다.
  3. 불확실한 판독은 사용자가 확인합니다. 확인을 마친 서류도 서류함에서 다시 열어 고칠 수 있습니다. 값을 고치면 지난 점검이 지워져 다시 점검해야 하고, 값이 그대로면 다시 보내지 않습니다.
  4. 가게 이름·신청인과 실제 폐업일을 받아 코드 규칙으로 대조합니다. 직접 입력한 가게 이름은 Case에 저장하고, 서류에서 읽은 상호로 덮어쓰지 않습니다.
  5. 문제가 없으면 점검된 서류와 요약 ZIP을 받습니다.

지원 형식과 제한#

20,000,000바이트 이하, 암호 없는 30쪽 이하 문서를 받습니다. 손상·과도한 페이지 크기·지원하지 않는 형식은 거부합니다. 현재 FE 업로드 제한 시간은 110초입니다.

점검 항목#

누락, 공사내역서·세금계산서·이체 금액, 거래처·수취인·신청인·공급받는 자, 실제 폐업일, 같은 전후 사진을 대조합니다. 통장 사본은 필수 정산 목록이 아니며 카드 결제 대체 서류 경로는 아직 없습니다.

읽기와 대조

OCR·모델은 문서의 종류와 값을 읽습니다. 금액·이름·날짜의 대조는 코드로 실행합니다. 서비스 점검 통과는 기관의 적격 판단이 아닙니다.

안전 검사 결과와 복구#

최신 구현은 안전 검사 차단을 일반 업로드 실패와 구분합니다. 같은 파일 재업로드를 반복 권하지 않습니다.

상황응답·화면 분기
AGENT_SAFETY_REFUSE422 detail.code, 처리하지 않았음을 알리고 내용 확인·다른 파일 안내
AGENT_SAFETY_CRISIS_SUPPORT422 detail.code, 진행·서류를 보존하고 상담 창구 안내
모델·OCR 실패502, 잠시 뒤 재시도 안내
시간 초과기존 서류 재조회, 같은 파일의 처리 상태 확인
JSON · 응답 형식 예시
{
  "detail": {
    "code": "AGENT_SAFETY_REFUSE",
    "message": "이 파일은 자동으로 읽지 않았어요. 서류 내용을 확인한 뒤 다른 파일로 올려 주세요."
  }
}

서류 변경과 재판단#

확인된 원상복구 조항이 새로 생기거나 바뀌면 DOCUMENT_SUBMITTED 판단을 예약합니다. 동일 조항·금액 서류 추가·삭제를 이유로 같은 재판단을 반복하지 않습니다. 판단 중이면 보류했다가 이어서 처리합니다.

DB에 보관하는 목록과 파일 산출물#

서류 목록·추출값·점검 상태와 마지막 판단에 사용한 context는 MySQL의 case_document_context에 저장합니다. 업로드 분석 중에는 긴 DB 잠금을 잡지 않고, 저장 직전 최신 목록과 비교해 그사이 삭제하거나 확인한 값을 보존합니다. 점검 도중 서류가 바뀌면 과거 점검 통과를 적용하지 않습니다. 처리한 PDF와 분석 캐시 등 산출물은 Case별 서버 파일 저장소에 남으며, 목록 삭제가 모든 파일의 영구 삭제를 뜻하지는 않습니다.

제출 파일#

현재 문서 digest·가림 정책·파일 무결성과 COMPLETE를 확인한 뒤 ZIP을 제공합니다. 서류가 바뀌면 지난 점검은 무효가 됩니다. 파일을 받은 뒤 외부 기관에 직접 제출합니다.
