자동으로 덮어쓰지 않는 이유#

새 입력이 들어왔다는 이유로 기존 사실을 바꾸면 중요한 상태가 사라집니다. 기존값과 충돌하는 후보가 나오면 멈추고 어느 값을 쓸지 사용자에게 선택받습니다.

처리 순서#

충돌 항목은 미리 선택하지 않습니다. 사용자의 선택 뒤에도 계획은 다시 검수해야 합니다.

  1. 충돌 후보와 기존값을 보관하고 Case는 유지합니다.
  2. 항목별 STORED 또는 PROPOSED를 받습니다.
  3. 유효한 현재 충돌인지 검증하고 PENDING을 접수합니다.
  4. 선택한 사실로 재판단·Review를 수행합니다.
  5. 성공하면 상태 변경과 충돌 해결을 함께 저장합니다.

실패와 재접속#

결정 뒤 판단에 실패하면 충돌 확인 화면에 머물며 선택과 실패 이유를 보여줍니다. 재시도 가능한 실패만 같은 선택으로 다시 보낼 수 있고, 재시도 불가로 실패한 선택 조합은 같은 충돌 묶음에서 반복 전송하지 못하게 합니다. 미해결 충돌과 기존 Case는 유지합니다. 다른 Case 참조·낡은 선택·동시 결정은 서버에서 거부합니다. 직접 URL 진입처럼 충돌 정보가 없는 화면은 안전한 진입점으로 돌아갑니다.
