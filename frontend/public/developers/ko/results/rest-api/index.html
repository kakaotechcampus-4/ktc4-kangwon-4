결과 알려주기 REST API

입력 가능한 결과를 확인하고 실행 결과를 접수·조회합니다.

코드 기준 4188520 · 확인 2026-11-11
이해하기REST API에러 코드
요청 경로와 인증

표는 Backend 경로입니다. 예제의 REBORN_API_BASE_URL은 Backend 주소(로컬 기본 http://localhost:8000)로 설정합니다. FE의 같은 출처 프록시 주소를 쓸 때는 /api까지 포함합니다. 리본 API에는 리본 자체 JWT를 Access-Token 헤더로 보냅니다. 카카오 토큰과 구분하세요.

결과 입력 진입 상태

입력 종류·최신 판단 번호·추가 질문·충돌을 확인합니다. 이전 화면의 오래된 값을 재사용하지 않습니다.

메서드URL인증 방식
GET/cases/results리본 Access-Token

요구 사항

유효한 리본 Access-Token과 현재 회원의 Case가 필요합니다. 각 API의 최신 이력·충돌·문서 상태 조건을 확인하세요.

실행 결과 접수

raw_input·restoration_answer·action_done·restoration_status 중 정확히 하나만 전달합니다. 선택형은 현재 행동과 허용된 같은 답 재시도 조건을 만족해야 합니다. HTTP 200은 접수이며 반영 완료가 아닙니다.

메서드URL인증 방식
POST/cases/results리본 Access-Token

요구 사항

유효한 리본 Access-Token과 현재 회원의 Case가 필요합니다. 각 API의 최신 이력·충돌·문서 상태 조건을 확인하세요.

본문 · application/json

이름타입설명필수
action_doneEnum / null고정값: true · 네 입력 중 정확히 하나만 전달X*
case_history_idInteger판단 또는 접수 이력 번호O
raw_inputString / null최소 길이: 1 · 최대 길이: 2000 · 네 입력 중 정확히 하나만 전달X*
restoration_answerRestorationAnswer / null사용자가 고른 원상복구 범위와 철거 여부 · 네 입력 중 정확히 하나만 전달X*
restoration_statusEnum / null사용 가능한 값: NOT_STARTED, IN_PROGRESS, COMPLETED · 네 입력 중 정확히 하나만 전달X*

* raw_input·restoration_answer·action_done·restoration_status 중 정확히 하나만 전달합니다. 화면의 질문과 답을 묶은 글도 전체 길이 제한을 확인합니다. ACTION_DONE은 action_done: true만, RESTORATION_STATUS는 NOT_STARTED·IN_PROGRESS·COMPLETED만 받으며 현재 행동·질문과 맞아야 합니다.

JSON · 완료 버튼 요청 예시
{
  "case_history_id": 12,
  "action_done": true
}
JSON · 진행 상태 요청 예시
{
  "case_history_id": 12,
  "restoration_status": "IN_PROGRESS"
}
cURL · 자리 표시자를 바꾸어 사용
curl -X POST "${REBORN_API_BASE_URL}/cases/results" \
  -H "Access-Token: ${ACCESS_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
  "case_history_id": 12,
  "restoration_answer": {
    "demolition_required": "REQUIRED",
    "restoration_scope": "PARTIAL"
  }
}'
