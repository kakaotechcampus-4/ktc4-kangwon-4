AI 실행 구조

LangGraph가 정한 실행 경로와 구성요소의 책임을 설명합니다.

코드 기준 4188520 · 확인 2026-11-11

MVP 실행 경로#

Procedure → Info → Supervisor → Review 순서로 진행합니다. 충돌은 사용자 선택을 받은 뒤 다시 판단합니다. Support는 현재 경로에서 호출하지 않습니다.

  1. Procedure: 검수된 공식 자료와 조건·절차 근거를 준비합니다.
  2. Info: 사실·진행·충돌 후보를 근거와 함께 추출합니다.
  3. Supervisor: 검증된 행동 후보에서 하나를 선택하거나 질문합니다.
  4. Review: 코드 검사 또는 모델 검수와 코드 검사로 검수합니다.
  5. BE: 검수된 변경 후보를 최신 상태와 대조하고 저장합니다.

모델을 생략하는 경로#

선택형 답은 Info 모델로 재해석하지 않습니다. 검수 정리본이 충분한 첫 판단·충돌 확인 후 처리도 가능한 경우 코드로 채웁니다. 모델이 만든 사실·문장이 없고 첫 검수인 등 제한된 조건에서는 code-only Review를 사용합니다.

필수 검수

모든 정상 계획은 Review 경계를 통과합니다. 모든 계획에서 별도 Review LLM을 호출한다는 뜻은 아닙니다.

실행 한도#

기본 모델 호출 예산 40회와 실행 제한 420초를 한 실행의 client들이 공유합니다. Review 재작업은 최대 2회이며 코드가 고정한 blocker 목록만을 문제 삼은 모델 반려는 수정 가능한 판정에서 제외하지만, 다른 계약·안전 이슈까지 제거하지 않습니다. 적용 가능한 반려와 원인·담당 구성요소는 진단 기록에 남깁니다. 이 값은 평균 시간이나 실제 호출 수가 아닙니다.

사용 기술#

LangGraph는 실행 순서를, Pydantic은 계약 검증을, httpx는 OpenAI 호환 endpoint 통신을 맡습니다. LangChain·Chroma·OpenAI SDK의 설치와 현재 실행 사용을 구분합니다. 요청 중 웹 수집·벡터 검색 RAG는 현재 경로가 아닙니다.
