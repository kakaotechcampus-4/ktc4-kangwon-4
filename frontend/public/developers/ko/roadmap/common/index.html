폐업 로드맵

전체 순서와 작업별 진행을 확인합니다.

코드 기준 5a8d11a · 확인 2026-11-11
이해하기REST API에러 코드

다섯 단계#

폐업 준비, 원상복구·철거, 영업 마무리·폐업 신고, 지원금 정산·가게 반환, 세금·마무리로 묶어 보여줍니다. 현재 작업 정의는 26개이며 가게마다 해당 여부와 상태가 달라집니다.

진행 상태#

단계는 작업을 묶는 구조입니다. 실제 영업 종료와 철거의 순서는 현재 조건과 안내를 함께 확인해야 하며 단계 번호만으로 결정하면 안 됩니다.

값의미
NOT_STARTED아직 시작하지 않음
IN_PROGRESS진행 중
COMPLETED완료로 기록됨
NOT_APPLICABLE이 가게에 해당 없음
NEEDS_CONFIRMATION조건 또는 사실 확인 필요

절차 안내 종료와 Case 완료#

PROCEDURES_COMPLETED는 Review를 통과한 등록 절차 안내 종료입니다. 홈과 작업 기록에 종료를 표시하고, 결과·충돌 처리 뒤 홈으로 이동합니다. 기관 신고·지원금 지급·모든 폐업 업무의 완료를 보증하지 않으며 Case의 COMPLETED와도 다릅니다. Case 완료는 별도로 vat_submission 체크와 연결됩니다. 확인된 원상복구 범위·철거 여부는 범위 확인 작업에 반영하고, 준비 확인과 실제 작업 진행을 혼동하지 않습니다.

작업별 입력#

체크·서류 첨부·심사 결과·폐업 정보·보증금 기록·실행 결과 보고를 작업 성격에 맞게 연결합니다.

작업입력과 의미
사용자 체크저장 성공 뒤 완료 표시, 완료 취소 가능
사진·증명원서류함에 올리기 연결, 체크와 파일 존재는 별개
1차 적격심사기관에서 받은 결과 true·false·null 기록
통합 폐업 신고실제 폐업일·사유·주소 저장, 기관 접수 API 아님
보증금FULL·PARTIAL·NONE의 기록, AI 분쟁 판단 아님
공식 절차결과 보고와 재판단으로 진행 확인

서비스 완료#

현재 구현은 vat_submission 체크에 Case COMPLETED를 연결합니다. 이 체크를 풀면 다시 진행 중으로 바뀝니다. 다른 세금 확인 작업은 남아 있을 수 있으므로 모든 외부 의무가 끝났다는 보증과 구분합니다.

확인 필요 작업

NEEDS_CONFIRMATION 항목은 [다 했어요]를 잠그며 서버도 완료 요청을 거부합니다. 체크했다고 공식 접수·심사 통과로 승격하지 않습니다.
