코드 기준 5a8d11a · 확인 2026-11-11
이해하기REST API에러 코드
요청 경로와 인증

표는 Backend 경로입니다. 예제의 REBORN_API_BASE_URL은 Backend 주소(로컬 기본 http://localhost:8000)로 설정합니다. FE의 같은 출처 프록시 주소를 쓸 때는 /api까지 포함합니다. 리본 API에는 리본 자체 JWT를 Access-Token 헤더로 보냅니다. 카카오 토큰과 구분하세요.

실패 판단 재개

허용된 CASE_CREATED·USER_INPUT·DOCUMENT_SUBMITTED 실패 이력을 같은 입력으로 PENDING으로 되돌립니다. 완료 Case나 허용하지 않은 상태는 409입니다.

메서드URL인증 방식
POST/cases/retry리본 Access-Token

요구 사항

유효한 리본 Access-Token과 현재 회원의 Case가 필요합니다. 각 API의 최신 이력·충돌·문서 상태 조건을 확인하세요.

요청

헤더설명필수
Access-Token리본이 발급한 해당 유형의 JWTO

요청 본문 없음

cURL · 자리 표시자를 바꾸어 사용
curl -X POST "${REBORN_API_BASE_URL}/cases/retry" \
  -H "Access-Token: ${ACCESS_TOKEN}"

접수와 반영 완료

성공 응답은 접수 상태입니다. 저장된 새 번호 또는 재개한 번호로 상태를 조회하고 업무 결과를 확인합니다.

에러 코드와 복구 · 타입과 필드

서버·DB 상태 확인

별도 DB 연결로 SELECT 1을 확인합니다. 성공하면 200 status: ok, DB 오류면 503 status: unavailable입니다. 양쪽 응답 모두 빌드 커밋 version을 포함하며 미설정 시 unknown입니다. 모델 연결까지 확인하지는 않습니다.
